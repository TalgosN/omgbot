# Виарыч: карта экранов и план desktop-адаптации

Дата: 30.10.2026. Первый этап по запросу пользователя — главная и Taskboard.

## Устройство интерфейса

Приложение использует отдельные HTML-страницы из `kpi_static`, выдаваемые Flask-маршрутами в `kpi_web.py`. На каждой странице — свой JS и CSS; общей компонентной библиотеки и сборщика нет. Общие механизмы: `app_ux.js/css` (черновики, отправка, состояния), `swipe_navigation.js` (навигация), `employee_preview.js` (режим сотрудника). API и права определяются сервером.

Светлая главная использует `home.css`; модули сохраняют свои тёмные палитры, градиенты и шрифты Furore/Montserrat. Текущие ограничения ширины 760–940 px и мобильные размеры текста не подходят для широкого рабочего окна. Диалоги уже поддерживают клавиатурное закрытие; камера имеет отдельную компоновку с безопасными областями.

## Общие компоненты первого этапа

- `desktop_shell.js/css`: навигация между существующими модулями, текущий раздел, пользователь и кнопка разворачивания при поддержке Telegram.
- `home_desktop.css`: отдельная композиция главной с сохранением исходного DOM и данных.
- `problems_desktop.css`: рабочая область заявок, аналитика, каталог и формы.
- Существующий диалог заявки переиспользуется как правая немодальная панель на широком окне. На узком окне он остаётся модальным. Данные, обработчики и идентификаторы общие.

Подключение ограничено двумя страницами. Остальные модули доступны по ссылкам, их desktop-композиция пока не меняется. Backend, права и API остаются прежними.

## Размеры и поведение

- До 768 px: существующий мобильный интерфейс.
- 768–1023 px: компактные сетки и инструменты; детали заявки модальные.
- От 1024 px: навигационная панель и master-detail Taskboard; до 1280 px навигация компактная.
- От 1920 px: дополнительные колонки там, где достаточно содержимого; читаемые размеры текста без пропорционального раздувания.

Режим определяется шириной viewport, не названием устройства. При изменении размера выбранная заявка и введённый комментарий должны сохраняться. Escape закрывает текущую панель/диалог, фильтры и список сохраняют контекст. Выбор заявки должен быть защищён от запоздавших ответов другого запроса.

## Проверка первого этапа

Проверить главную для владельца, менеджера, сотрудника и КЦ; Taskboard — список, выбор, длинные тексты, фильтры, комментарий, решение, создание, аналитику и справочники. Проверить пустые состояния, ошибки, клавиатуру и изменение размера при открытых деталях.

Разрешения: 390×844, 768×1024, 1024×768, 1366×768, 1920×1080, 2560×1440. Браузерная проверка использует изолированные демонстрационные ответы API и не изменяет рабочие данные. Поддержку реального полноэкранного режима Telegram Desktop/Web необходимо дополнительно проверить в самих клиентах.

## Результат первого этапа

Реализованы главная и Taskboard с вложенными формами, аналитикой, справочником и сеткой оборудования. Общая навигация подключена только к этим страницам. На широком окне детали заявки немодальные, на узком — модальные; используется один DOM-узел с прежними обработчиками. Добавлена защита от запоздавшего ответа при переключении заявки и освобождение временных ссылок на вложения.

Проверено в Microsoft Edge через Playwright:

- Обе страницы на всех шести разрешениях; горизонтального переполнения страницы нет.
- Главная для владельца, менеджера, сотрудника клуба и КЦ.
- Выбор и подсветка заявки, закрытие через Escape, переход между немодальным и модальным представлением без потери введённого комментария.
- Добавление комментария и отправка решения на проверку через демонстрационный API.
- Запоздавший ответ ранее выбранной заявки не заменяет новую.
- Создание ремонта, аналитика, справочник, пустое оборудование и пустой результат фильтрации.
- Скрытие управленческих инструментов и формы комментария у сотрудника.
- Геометрия мобильной главной и списка Taskboard при 390 px совпадает с исходным `HEAD` на момент проверки.
- Существующий браузерный сценарий восстановления черновиков и отправки файлов проходит.
- 22 серверные проверки страниц/Taskboard/ремонтов/оборудования и 5 проверок фотоинтерфейса проходят.

Полный файл `test_kpi_web.py`: 85 из 89 тестов прошли. Один тест выбора смены использует фиксированную дату 03.09.2026, вышедшую за текущий диапазон выбора; три других получают `sqlite3.DatabaseError: database disk image is malformed` при обращении к настроенной базе вместо изолированного набора данных. Backend и эти тесты в рамках desktop-адаптации не изменялись. Общий набор нельзя считать полностью пройденным.

Скриншоты создаёт `python scripts/check_desktop_ui.py` во временной директории, которую скрипт печатает в конце. Для запуска нужны Playwright и Microsoft Edge. Реальные Telegram Desktop/Web и физические телефоны отдельно не проверялись. Кнопка разворачивания доступна только при заявленной клиентом поддержке API; автоматическое изменение размера нативного окна в этот этап не включено.

Публикация и изменение серверной конфигурации не выполнялись. Следующие кандидаты на адаптацию — KPI и Shift, с сохранением общих данных и новой навигации.
