# Steam Tracker: инструкция владельца и внедрение

## 1. Архитектура

Рабочая схема:

`Telegram-бот → SQLite → Google Sheets`

- `db/steamtracker_v2.db` — единственный источник каталога, аккаунтов,
  настроек, лицензий, промо и аудита.
- Telegram-бот — единственная панель управления.
- Google Sheets — только отчёты для просмотра и формул.
- Steam Web API — наличие купленных лицензий и игровое время.
- Steam Store API — название, базовое описание, жанры и изображения.
- OpenRouter — генерация текстов.

Старый поток `Google Sheets → SQLite` отключён. Значение
`STEAMTRACKER_CATALOG_SYNC_ENABLED` теперь игнорируется, а CLI-команда
`sync-catalog-sheets` не изменяет данные.

## 2. Роли

### Сотрудник

- видит `Steam Tracker` в главном меню сразу после `Расписания`;
- просматривает только активные игры;
- открывает карточки и проверяет наличие игры на активных ПК;
- не может менять каталог, статусы, данные Steam или промо.

### Менеджер

- рабочие и тестовые промо;
- согласование и редактирование;
- каталог игр;
- история изменений.

### Владелец

Имеет все права менеджера, а также:

- Steam-аккаунты и ПК;
- системные настройки игры недели;
- ручные синхронизации;
- включение автоматического режима;
- перехват промо;
- полное удаление тестового промо.

## 3. Что произойдёт после обновления

При первом запуске новой версии `storage.initialize()` автоматически:

1. создаст недостающие таблицы настроек и аудита;
2. добавит новые поля каталога;
3. перенесёт все существующие `is_approved=1` игры в управляемый статус
   `active`;
4. оставит все промо, тексты, ротацию, лицензии и историю без удаления;
5. создаст безопасные настройки по умолчанию;
6. установит `weekly_promo_enabled=false` внутри SQLite.

Технические Steam-приложения, которые просто встречались в библиотеках,
не станут менеджерскими черновиками.

Перед внедрением обязательно сделайте резервную копию SQLite.

## 4. Настройки `.env`

Рекомендуемый безопасный блок:

```dotenv
# Рабочая SQLite-база Steam Tracker.
STEAMTRACKER_DB_PATH=db/steamtracker_v2.db

# Legacy-база нужна только старым операциям переноса.
STEAMTRACKER_LEGACY_DB_PATH=dump/steamtracker/steam_stats.db

# Лицензия снимается только после трёх успешных проверок отсутствия.
LICENSE_REMOVAL_THRESHOLD=3

# Пока публикация не внедрена, оставлять только dry_run.
PUBLISH_MODE=dry_run

# Steam Web API. Нужен для проверки библиотек.
STEAM_API_KEY=

# Автоматическая проверка лицензий при старте и каждые четыре часа.
STEAMTRACKER_SYNC_ENABLED=true

# Ежедневное обновление Steam Store-данных.
STEAMTRACKER_STORE_ENRICHMENT_ENABLED=true

# Таблица, куда выгружаются отчётные листы.
STEAMTRACKER_SPREADSHEET_ID=

# JSON service account Google.
STEAMTRACKER_GOOGLE_SERVICE_ACCOUNT_FILE=key/service-account.json

# Устарело, всегда оставлять false.
STEAMTRACKER_CATALOG_SYNC_ENABLED=false

# Разрешить отчётную выгрузку SQLite → Google.
STEAMTRACKER_GOOGLE_EXPORT_ENABLED=true

# Главный серверный предохранитель автоматической игры недели.
STEAMTRACKER_WEEKLY_PROMO_ENABLED=true

# fake — тест без LLM; openrouter — настоящая генерация.
STEAMTRACKER_GENERATOR=openrouter
OPENROUTER_API_KEY=
OPENROUTER_MODEL=deepseek/deepseek-v4-flash

# Отправка карточки на согласование указанным Telegram ID.
STEAMTRACKER_TELEGRAM_APPROVAL_ENABLED=true
STEAMTRACKER_APPROVER_IDS=592831529

# Реальные внешние отправки пока выключены.
EMPLOYEE_DELIVERY_ENABLED=false
TELEGRAM_SOCIAL_ENABLED=false
VK_PUBLISH_ENABLED=false
```

Автоматический режим включается только при двух одновременных условиях:

1. `STEAMTRACKER_WEEKLY_PROMO_ENABLED=true` в `.env`;
2. `weekly_promo_enabled=true` в настройках Telegram-бота.

Это позволяет мгновенно выключить автоматизацию из Telegram, сохраняя
серверный аварийный выключатель.

## 5. Первый деплой

На сервере из корня проекта:

```bash
cp db/steamtracker_v2.db db/steamtracker_v2.before_bot_management.db
docker compose build bot
docker compose run --rm bot python -m unittest discover \
  -s tests \
  -p "test_steamtracker*.py" \
  -v
docker compose up -d bot
docker compose logs --tail=200 bot
```

Обратите внимание: символ продолжения строки в Linux — `\`, а не
PowerShell backtick.

После старта проверить миграцию:

```bash
docker compose run --rm bot python steamtracker_cli.py status
docker compose run --rm bot python steamtracker_cli.py weekly-promo
```

`weekly-promo` без `--apply` ничего не создаёт.

## 6. Первичная проверка в Telegram

1. Открыть `Главное меню → 🎮 Steam Tracker`.
2. Проверить наличие разделов:
   - `Промо`;
   - `Каталог игр`;
   - `ПК и аккаунты`;
   - `Настройки`;
   - `Синхронизация`;
   - `История изменений`.
3. Открыть каталог и проверить несколько игр.
4. Открыть `Без лицензии`.
5. Открыть Steam-аккаунты и проверить клубы/зоны.
6. Открыть настройки: после миграции автоматизация внутри бота выключена.
7. Выполнить ручную выгрузку Google.
8. Создать тестовое промо.
9. Создать рабочее промо вручную и пройти согласование в dry-run.

## 7. Управление Steam-аккаунтами

Путь:

`🎮 Steam Tracker → 💻 ПК и аккаунты`

### Добавление

Нажмите `Добавить Steam-аккаунт` и отправьте:

```text
SteamID | название зоны | точное название клуба
```

Пример:

```text
76561198000000000 | pc-5 | OMG VR Арбат
```

Название клуба должно существовать в текущем `clubs.json`.

После добавления:

1. откройте карточку;
2. нажмите `Проверить лицензии сейчас`;
3. проверьте количество найденных игр;
4. выгрузите Google-отчёт при необходимости.

### Редактирование

В карточке аккаунта выберите изменение и отправьте:

```text
новое название зоны | точное название клуба
```

### Отключение

Аккаунты никогда не удаляются физически. Кнопка `Отключить`:

- исключает аккаунт из последующих Steam-проверок;
- исключает его лицензии из доступности;
- сохраняет всю историю;
- автоматически ставит на паузу активные игры, если это была их последняя
  лицензия.

Повторное включение не активирует такие игры автоматически. Сначала
синхронизируйте библиотеку, затем активируйте игры вручную.

## 8. Управление каталогом

Путь:

`🎮 Steam Tracker → 🕹 Каталог игр`

Новая игра добавляется только по AppID. Бот получает официальное Steam-
название и создаёт черновик. После этого:

1. укажите количество игроков;
2. при необходимости добавьте менеджерское описание;
3. проверьте наличие по ПК;
4. активируйте.

Активация блокируется без лицензии. Сам факт существования приложения в
Steam Store недостаточен.

Статусы:

- `active` — участвует в промо и отчётной матрице;
- `draft` — готовится;
- `paused` — временно исключена;
- `excluded` — долгосрочно исключена без удаления истории.

В карточке игры изменение полей и изменение статуса находятся в отдельных
подменю. Экран наличия не выводит полный список исправных ПК: он показывает
только отсутствующие лицензии либо сообщение, что игра есть везде.
Карточка также показывает обложку Steam Store, сумму lifetime playtime на
всех активных клубных Steam-аккаунтах и место игры по этой сумме среди
активного каталога. Рейтинг начинается с `1`; одинаковое время даёт
одинаковое место.

Общий отчёт доступен через
`Каталог игр → Отсутствующие лицензии`. Он учитывает только активные игры
и активные аккаунты, группирует проблемы по клубам и показывает конкретные
игры и зоны.

### Разовое заполнение менеджерских описаний

Генерация использует текущие `OPENROUTER_API_KEY` и `OPENROUTER_MODEL`, но
не изменяет SQLite. Для пилота из пяти игр:

```bash
docker compose run --rm bot python steamtracker_cli.py \
  generate-manager-descriptions --limit 5
```

Черновики сохраняются на сервере в
`Reports/steamtracker_manager_descriptions.json`. Внутри можно отредактировать
поле `proposed_description`, не меняя AppID, название и fingerprint.

Продолжить с оставшихся игр и повторить неудачные запросы:

```bash
docker compose run --rm bot python steamtracker_cli.py \
  generate-manager-descriptions --resume --workers 3
```

Для выборочного пилота вместо `--limit` можно несколько раз передать
`--app-id`:

```bash
docker compose run --rm bot python steamtracker_cli.py \
  generate-manager-descriptions \
  --app-id 620980 \
  --app-id 555160
```

`--workers` задаёт от 1 до 5 параллельных запросов. По умолчанию используется
один; для массового разового запуска достаточно трёх.

После проверки применить готовые тексты:

```bash
docker compose run --rm bot python steamtracker_cli.py \
  apply-manager-descriptions \
  --confirm APPLY_MANAGER_DESCRIPTIONS
```

Применяются только записи со статусом `generated`. Игра должна оставаться
активной, её название и исходные Steam-данные не должны измениться.
Существующее ручное описание никогда не перезаписывается. Каждая запись
фиксируется в аудите как `game_updated`.

## 9. Настройки игры недели

Путь:

`🎮 Steam Tracker → ⚙️ Настройки`

Доступны:

- скидка;
- включение/выключение автоматизации;
- день недели;
- время;
- часовой пояс IANA;
- техническая очередь.

Начальные значения:

- скидка `100 рублей`;
- понедельник;
- `10:30`;
- `Europe/Moscow`;
- автоматический режим внутри SQLite выключен.

Планировщик проверяет настройки каждую минуту. В настроенный день после
настроенного времени он создаёт не более одного рабочего промо на неделю.
Если на этот период уже существовало рабочее промо, повторного автоматического
создания не будет даже после его отмены.

Ручной режим работает независимо от выключенной автоматизации:

`Промо → Рабочие промо → Создать рабочее промо`

## 10. Синхронизации

Путь:

`🎮 Steam Tracker → 🔄 Синхронизация`

### Проверить все лицензии

Запускает фоновую Steam Web API-проверку всех активных аккаунтов.

Автоматически она выполняется:

- сразу после запуска бота;
- каждые четыре часа.

Ошибка одного аккаунта не снимает его лицензии. Лицензия снимается только
после количества успешных отсутствий, заданного
`LICENSE_REMOVAL_THRESHOLD`.

### Обновить Steam Store

Фоново обновляет названия, описания, жанры, категории и изображения
управляемых игр. Автоматический запуск — ежедневно в 05:30 МСК.

### Выгрузить отчёты в Google

Перезаписывает отчётные листы текущим состоянием SQLite. Google при этом
ничего не возвращает обратно.

## 11. Отчётные листы Google

### `Игры`

Все управляемые игры, включая черновики, паузу и исключённые. Включает
AppID, Steam-название, описание, метаданные, наличие лицензий и историю
ротации.

### `Current_State`

Матрица активных игр и активных Steam-аккаунтов. Для отсутствующей
лицензии явно записывается `owned=0`. Ключ игры — `steam_app_id`.

### `Steam Динамика`

Только положительный прирост игрового времени по активным играм.

### `Промо-план`

Отчётная история промо и текстов.

### `Настройки Steam Tracker`

Зеркало SQLite-настроек. Редактирование листа вручную не применяется.

## 12. Ручные CLI-команды

Статус:

```bash
docker compose run --rm bot python steamtracker_cli.py status
```

Предпросмотр игры недели:

```bash
docker compose run --rm bot python steamtracker_cli.py weekly-promo
```

Принудительное ручное создание:

```bash
docker compose run --rm bot python steamtracker_cli.py weekly-promo \
  --apply --force
```

Отчётная выгрузка:

```bash
docker compose run --rm bot python steamtracker_cli.py \
  sync-data-sheets --apply
```

Обновление Steam Store:

```bash
docker compose run --rm bot python steamtracker_cli.py enrich-store
```

Команду ниже больше не использовать:

```bash
docker compose run --rm bot python steamtracker_cli.py \
  sync-catalog-sheets --apply
```

Она намеренно завершится сообщением, что каталог управляется через бот.

## 13. Проверка автоматического режима

1. В `.env` установить
   `STEAMTRACKER_WEEKLY_PROMO_ENABLED=true`.
2. Перезапустить контейнер.
3. В боте открыть настройки Steam Tracker.
4. Установить день, время и часовой пояс.
5. Включить автогенерацию.
6. До наступления времени проверить:

```bash
docker compose run --rm bot python steamtracker_cli.py weekly-promo
```

7. После запуска проверить логи и карточку согласования.

Карточка отправляется каждому Telegram ID из
`STEAMTRACKER_APPROVER_IDS`, если
`STEAMTRACKER_TELEGRAM_APPROVAL_ENABLED=true`.

## 14. Резервное копирование и восстановление

Минимальная резервная копия:

```bash
cp db/steamtracker_v2.db \
  "db/steamtracker_v2.$(date +%Y%m%d_%H%M%S).db"
```

Перед восстановлением остановите bot:

```bash
docker compose stop bot
cp db/steamtracker_v2.before_bot_management.db db/steamtracker_v2.db
docker compose up -d bot
```

Не используйте `git reset --hard` для базы: SQLite обычно не хранится как
версионируемый рабочий файл.

## 15. Диагностика

### Steam API

- проверить `STEAM_API_KEY`;
- проверить `STEAMTRACKER_SYNC_ENABLED=true`;
- открыть карточку одного аккаунта и выполнить ручную проверку;
- посмотреть логи контейнера.

### OpenRouter

- проверить `OPENROUTER_API_KEY`;
- проверить `STEAMTRACKER_GENERATOR=openrouter`;
- открыть `Админ-панель → Дополнительно → Статус систем`.

### Google

- проверить Spreadsheet ID;
- проверить путь к service account внутри контейнера;
- предоставить service account права редактора таблицы;
- выполнить ручную выгрузку из Telegram.

### Автоматическая игра недели не появилась

Проверить:

1. серверный флаг `.env`;
2. внутренний флаг в Telegram;
3. день, время и часовой пояс;
4. наличие активной игры с лицензией;
5. существовало ли уже рабочее промо на эту неделю;
6. доступность OpenRouter;
7. логи контейнера.

## 16. Границы текущей версии

Сейчас полностью работают:

- учёт лицензий;
- динамика игрового времени;
- каталог через Telegram;
- аккаунты через Telegram;
- настройки и расписание через Telegram;
- генерация и согласование промо;
- dry-run очередь;
- отчётная выгрузка Google;
- аудит административных изменений.

Пока намеренно не работают:

- реальная отправка сотрудникам;
- реальная публикация Telegram;
- реальная публикация VK.

До отдельного внедрения публикации необходимо сохранять
`PUBLISH_MODE=dry_run` и три флага доставки `false`.
